`Button` owns every part of its presentation. Callers control placement and the documented
props only; do not override radius, padding, colour, hover, focus or pressed behaviour with
local classes.

## Props

| Prop | Values | Notes |
| --- | --- | --- |
| `variant` | `filled`, `outline`, `transparent` | Visual treatment |
| `colorScheme` | keys of `COLOR_PALETTE` | Semantic colour token, not a raw CSS colour |
| `borderColor` | `background`, `foreground`, `faded` | Only meaningful with a bordered variant |
| `size` | `xsmall`, `small`, `default`, `medium`, `large`, `xlarge` | Utility-driven sizing |
| `textCase` | `uppercase`, `title`, `lowercase` | Typography token |
| `clickable` | boolean | Adds pointer affordance to otherwise static styling |
| `hasIcon` / `iconPosition` | boolean / `left`, `right` | Icon child placement |
| `isLoading` / `disabled` | boolean | Loading and disabled presentation |

## Responsive behaviour

Buttons keep their intrinsic width and wrap within a flex container. On narrow screens the
variant grid stacks by row; no nested horizontal scrolling is introduced by the docs frame.

## Usage

```tsx
import { Button } from '@/components/ui/Button';

<Button variant="filled" colorScheme="lake-forest" onClick={continueBooking}>
  Book Your Stay
</Button>
```
